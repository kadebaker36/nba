# Cloud daily research with one focused audit

This workflow supersedes the four-role bootstrap for daily research. METHOD.md remains the canonical basketball policy. The existing official-schedule planner can be used independently of its legacy four-role profile configuration. Use lean_roles.json for research roles; never use daily_roles.json to launch the retired quartet.

Run on hosted cloud execution and authorized connected services. No personal computer, local daemon, manual Colab upload, paid model API service or user continuation prompts are required. A missing cloud execution or connection capability is a concrete blocked stage, not permission to move execution onto the user's computer. Scheduled provisioning still needs an actual live receipt; configuration is not proof of unattended success.

## Roles and cost boundaries

The minimal hosted launcher starts Worker with the exact controls in lean_roles.json and a complete seed containing the assigned slate, this workflow, the canonical policy reference and private workbook binding. Worker performs the refresh and all analysis, owns code and workbook writes, and directly produces the final report. There is no Admin or Bridge agent, relay chain, repeated setup test or ceremonial work-order loop.

Worker reads AGENTS.md, METHOD.md, docs/HANDOFF.md and docs/DATA_MAP.md once per run. Re-read only changed or disputed material. Validate cached source identities, actual cutoff and coverage; fetch missing or changed inputs. Do not re-fetch an accepted historical dataset just to demonstrate activity. Keep ordinary calculations and formatting in scripts. Reuse the accepted checkpoint after an interruption.

After completing a draft, Worker starts exactly one fresh Auditor, using gpt-6.1-sol/high and fork_turns=none. Supply METHOD.md, a compact evidence packet, source paths/hashes and the draft; Auditor reads those once and independently checks the material underlying figures and conclusions. Auditor does not repeat ingestion, read unrelated project history, spawn agents or edit the workbook. Use direct artifact references, not a relay agent. Inspect actual role status and use followup_task for an idle recipient.

Audit output is a short list of material errors or omissions with evidence, or acceptance. Worker performs at most one focused correction round and one targeted confirmation by the same Auditor when material corrections require it. No recursive review or replacement-agent loop. If a remaining defect cannot be resolved, deliver supported findings and identify the unresolved stage. An audit failure cannot be presented as approval. Report delivery does not wait for code documentation or packaging polish.

Name roles BBB - YYYY-MM-DD - Worker and BBB - YYYY-MM-DD - Auditor, using the assigned Chicago slate date. Record actual endpoints and accepted spawn controls. Self-identification is not independent runtime-model proof. If sidebar rename is unsupported, say so once in the receipt; do not spend a run trying to rename hosted subagents. Never silently substitute requested models.

## Sequential pass contract

Complete each row before proceeding to the next. A compact pass ledger must contain: stage, completed/partial/blocked status, cutoff and window, actual source reference, raw figures and units, eligible sample, percentiles when supported, offense strength, specific defensive concession, strongest contradiction, Advance/Watchlist/Reject decision, and the reason for each change from the previous pass. For a missing field or source, record the gap and its effect rather than marking the pass completed. A pass name or a checkbox alone is insufficient evidence.

| Order | Required attention and output | Influence |
| --- | --- | --- |
| 1. Volume, own shooting and pace | Screen both directions of the unstarted slate. Show offense 3PA/100, own 3P%, opponent 3PA allowed/100, raw counts, season and true last-10 windows, eligible samples and league percentiles. Apply expected possessions once for illustrative game attempts. Record decisions and contradictions. Raw opponent 3P% supplies no perimeter boost. | Part of the core 92.5%; no invented split between passes 1 and 2. |
| 2. Shot quality and schedule adjustment | Test advance/watchlist candidates with matched tracking, open and wide-open rates, expected makes/100, leave-one-defense-out baseline, adjusted difference, volume-versus-mix decomposition, expected make rate and full-shot sensitivity. Show absolute baseline differences and coverage; omit unsupported percentiles. Revise decisions explicitly. No advancement to the final shortlist without this assessment. | Remaining core judgment within the same 92.5%; do not count volume twice. |
| 3. Three-point creation | For surviving theses, examine catch-and-shoot opportunities/concessions when available, assisted 3PM/100, assisted share and observed creator-to-shooter links. Potential assists cover twos as well as threes; made assists depend on conversion. Trace likely shooter beneficiaries and state unavailable evidence. | Provisional 5%, applied once across team and player review. Cannot rescue a failed core thesis. |
| 4. Offensive rebounds | Check OREB%, opposing DREB weakness, personal rebound-to-next-three links and broader tagged second-chance threes separately. Explain any incremental opportunity beyond the offense's normal baseline. Update close decisions only. | Tiebreaker, at most 2.5%, applied once. Cannot rescue a failed core thesis. |
| Availability | Use current official injury reports plus credible local reporting. Compare absences/returns with what the statistical sample already contains. Estimate rotations with confidence and material alternatives; do not wait indefinitely for confirmed starters. | Proportional personnel adjustments under METHOD.md; no new arbitrary score. |
| Player review | First publish the final team audit: strength, conceded weakness, strongest contradiction, decision/reason. Review up to three qualifying teams one at a time. Use real player appearances, minutes, attempts, conversion, shared creator minutes, passing links and shot fit. Include non-stars/bench players when supported. Give conditional minutes/3PA and conservative/stretch 3PM ranges. | Carry earlier evidence forward; no extra assist/rebound bonus or player-based rescue of rejected teams. |

These are provisional judgment allowances, not calibrated probabilities or an additive scoring machine. Do not manufacture subweights, set attention by word count, fill a shortlist quota or veto a team using one metric. Every pass gets evidence and a decision even when its effect is small. Missing evidence produces partial/blocked status and a bounded limitation; continue independent supported work.

## Data and recovery checks

Use America/Chicago and an explicit previous-local-date statistical cutoff. Use only pre-tip evidence for pregame claims. An after-tip reconstruction is labelled retrospective; exclude the slate's game outcomes from analytical inputs and disclose incidental outcome exposure. Distinguish historical replay from newly fetched data and scheduling success from research completion.

Read the live existing workbook's Method, coverage and Pick Review before writes. Preserve user fields, notes, choices and policy. A no-delta refresh does not need manufactured writes. Verify written cells, actual hyperlink destinations, cutoff/coverage and preserved picks through readback.

Archive names and workbook link labels are not cutoff proof. Inspect the actual saved contents, manifests and hashes. Reconcile source corrections without forcing new valid data to equal an old snapshot. Preserve relevant before/after evidence.

NBA LastNGames plus DateTo can return fewer than the actual last ten completed games after later games finish. Verify actual as-of game selection for all 30 teams before league percentiles. Reconstruct valid windows from dated games and matched numerators/possessions/pace when necessary; retain the original response. Never label nine games as ten, invent missing rates or treat event validation as validation of every derived metric.

Keep one compact private date-keyed checkpoint with source manifests/data references, pass ledger, report draft, audit status and pending writes. Save meaningful progress before expensive continuation and reconcile live state after uncertain writes. Save the reproducible data package once when needed, not a new transcript bundle for every message. Scratch paths are temporary. Never put private workbook IDs, picks or saved-file IDs in public Git.

## Audit and delivery

Auditor must independently check dated source identity, actual windows, coverage, units, percentage scaling, sample/denominator handling and material source calculations. It checks all pass-ledger rows against evidence, schedule adjustment execution, no double-counting, the 92.5/5/max2.5 hierarchy, decision transitions, no forced shortlist, availability assumptions and each selected player's defensible ranges. It flags any unperformed pass, unsupported percentile, stale source, unlabelled partial or source mismatch. Access failure means audit incomplete, not acceptance.

Keep the audit packet focused (normally at most 1,500 words plus referenced tables/source files), audit response normally under 500 words, and final report normally under 1,500 words. These are output targets, not permission to skip required work or truncate material uncertainty. Do not repeatedly embed full source documents in messages. Deliver one report with the pass decision trail, final audit and per-team player tables, supported figures/percentiles, source times/cutoff, coverage and unresolved limitations. Larger evidence tables remain linked privately.

Scheduling stays separate from research: use the official schedule to set the existing worker's one-time launch to first tip minus 120 minutes, preserving a single launch per Chicago slate date. Respect user halts, skip verified no-game dates and never silently discard unresolved tips. The lightweight existing cloud schedule checker remains responsible for scheduling only. Do not claim it is a deployed non-LLM daemon. No betting orders, pricing, purchases, external messages to people or methodology changes are authorized by this workflow.
